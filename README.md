# Yandex 360 Domain Rules

CLI-скрипт для добавления и удаления доменов в правилах блокировки входящей почты Яндекс 360. Администратор видит текущие правила, вводит домен, выбирает действие и подтверждает изменение в терминале.

Используется действие **`reject`**: письма от отправителей на указанных доменах отклоняются.

> **Статус обновления:** автоматические тесты пройдены; ручная проверка нового CLI-сценария на рабочей организации продолжается.

## Как работает скрипт

1. Получает и выводит текущие правила с сервера.
2. Предлагает выбрать правило блокировки, если таких доменных правил несколько. Единственное подходящее правило выбирается автоматически.
3. Запрашивает домен для добавления или удаления.
4. Предлагает действие: **Добавить**, **Удалить** или **Выход**.
5. Показывает планируемое изменение и запрашивает подтверждение.
6. Сохраняет правила, повторно читает их с сервера и проверяет результат. При совпадении выводит **«Выполнено»** и обновлённое правило.

**Один запуск — одна операция с одним доменом.** Для следующего изменения запустите скрипт повторно.

## Требования

- Python 3.8 или новее.
- Библиотека `requests`.
- ID организации Яндекс 360.
- OAuth-токен с доступом к организации и правами:
  - `ya360_admin:mail_read_routing_rules` — чтение правил;
  - `ya360_admin:mail_write_routing_rules` — изменение правил.

## Установка

```sh
git clone https://github.com/MilekhinAV/Y360_domain_rules.git
cd Y360_domain_rules
python3 -m pip install -r requirements.txt
```

В Windows используйте `python` вместо `python3`, если Python установлен под этим именем.

## Настройка

Скрипт читает параметры из переменных окружения:

| Переменная | Значение |
| --- | --- |
| `Y360_ORG_ID` | Числовой ID организации |
| `Y360_OAUTH_TOKEN` | OAuth-токен для работы с API |

Пример для **Bash и zsh** в Linux или macOS — токен вводится скрыто и не записывается в текст команды:

```bash
export Y360_ORG_ID='1234567'
printf 'OAuth-токен: '
read -r -s Y360_OAUTH_TOKEN
printf '\n'
export Y360_OAUTH_TOKEN
```

Если используете другую оболочку, задайте эти две переменные её средствами.

Для локального запуска также можно заменить значения-заглушки `ваш_org_id` и `ваш_oauth_токен` в начале `main.py`. Переменные окружения имеют приоритет над этими значениями. Не отправляйте файл с настоящим токеном в GitHub.

### Пример добавления

Ниже JSON-блоки сокращены для наглядности; скрипт выводит их полностью.

```text
Текущие правила:
... JSON текущих правил ...

Изменяемое правило:
... JSON выбранного правила ...

Домен (например example.com или *.us; Enter — выход): example.com
1 — Добавить, 2 — Удалить, 0 — Выход: 1

Добавить домен: example.com
Правило после изменения:
... JSON будущего правила ...
Подтвердить? [да/НЕТ]: да

Выполнено: домен example.com добавлен.
Обновлённое правило с сервера:
... JSON прочитанного правила ...
```

### Удаление и отмена

Для удаления введите домен и выберите `2` или `Удалить`. Перед сохранением скрипт покажет результат изменения.

Если это последний домен в правиле, скрипт предупредит, что **удалит само правило**: API не допускает пустой список доменов. Удаление выполняется только после подтверждения; после него выводится оставшийся список правил.

Отменить операцию можно:

- нажать Enter вместо ввода домена;
- выбрать `0` или `Выход` в меню действий;
- нажать Enter или ответить `нет` на запрос подтверждения.

Сохранение подтверждается ответами `да`, `yes` или `y` без учёта регистра. Любой другой ответ отменяет его.

## Формат доменов

| Ввод | Значение |
| --- | --- |
| `example.com` | Домен отправителя `example.com` |
| `*.example.com` | Поддомены `example.com`; сам `example.com` нужно добавить отдельно |
| `*.us` | Домены в зоне `.us` |
| `пример.рф` | Кириллический домен; перед сохранением переводится в IDNA |

Вводите домен без `https://`, пути и имени почтового ящика. Регистр не учитывается, пробелы по краям и завершающая точка удаляются.

При удалении сопоставляется конкретная запись, а не все покрывающие её маски. Например, удаление `example.com` **не снимает блокировку по оставшейся маске `*.com`**.

## Особенности изменения правил

- Изменяются только доменные правила с действием `reject`. Правила `accept` и правила по IP-адресам или полным адресам отправителей не предлагаются для выбора.
- Если доменного правила блокировки нет, добавление создаёт включённое правило `Blocked domains` в конце списка. Удаление в этом случае ничего не меняет.
- Существующее правило сохраняет название, описание, активность, действие и место в списке. Изменение выключенного правила не включает его автоматически.
- Повторное добавление уже указанного домена и удаление отсутствующего домена завершаются без записи в API.
- Скрипт проверяет лимиты при добавлении: до 200 правил и до 200 доменов в одном правиле.
- Порядок правил влияет на результат: применяется первое подходящее активное правило. Более раннее правило может иметь приоритет над редактируемым.

API сохраняет список правил целиком. Скрипт передаёт остальные правила вместе с изменённым и повторно читает текущий список перед записью. Если за время диалога список изменился, сохранение отменяется с предложением повторить запуск.

Эта проверка не блокирует параллельное редактирование: между последним чтением и записью остаётся короткое окно. Избегайте одновременного изменения правил несколькими администраторами.

## Ошибки и проверка результата

Сообщение **«Выполнено»** появляется только после контрольного чтения и совпадения полученного списка с отправленным.

Если API принял запись, но контрольное чтение не удалось или вернуло другой список, скрипт сообщает, что результат не подтверждён. При тайм-ауте отправки результат может быть неизвестен. В обоих случаях запустите скрипт заново, посмотрите текущие правила и только затем решайте, нужна ли повторная операция. Автоматического повторного сохранения нет.

Коды завершения:

| Код | Значение |
| --- | --- |
| `0` | Успешное изменение, отмена или отсутствие необходимых изменений |
| `1` | Ошибка либо прерывание ввода |

## Тесты

```sh
python3 -m unittest -v
```

Тесты используют подставные ответы API и не меняют настройки организации. Проверяются добавление и удаление домена, удаление последнего домена, отмена, повторное добавление, выбор правила блокировки, сохранность других правил, проверка ввода, конфликт изменений, ошибки HTTP, тайм-аут и несовпадение контрольного результата.

```text

```
